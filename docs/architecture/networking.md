# Networking

The Go mesh (`apps/mesh`) is a child process of the agent; the relay (`apps/relay`) is optional infrastructure. Wire
contracts: `proto/mesh/v1/{ipc,frames,relay}.proto`. Game packets never touch the control plane.

## Identity & authentication

Each node's ed25519 key (generated by the agent, PKCS#8 PEM at `<data>/identity/node.key`) is used for a self-signed
X.509 certificate presented in QUIC/TLS 1.3 with mutual auth. Verification ignores the CA chain and instead pins: the
peer's certificate public key must equal the `public_key` the control plane listed for that peer's `node_id`
(`SetPeers`). ALPN `p2pgames/1`. Unknown keys are rejected — group membership is the trust boundary.

## Transport

`quic-go` with a single `quic.Transport` on one UDP socket (`listen_port`, default 41641, fallback ephemeral) used for
both listening and dialing (required for hole punching). Datagrams enabled. Keepalive 10 s, idle timeout 30 s.
One connection per peer pair: if both sides dial simultaneously, keep the connection initiated by the lexicographically
smaller `node_id` and close the other.

Non-QUIC packets on the same socket (first byte < 0x40) are relay frames, read via `Transport.ReadNonQUICPacket`.

### Path establishment (per peer, continuously)

1. Gather candidates: local interface addresses (`local_endpoints`) and relay-observed address (`observed_endpoints`),
   reported to the agent → CP → other peers via `SetPeers.endpoints`.
2. **Direct / hole punching**: dial all candidate endpoints concurrently (IPv6 first, then IPv4), repeating every
   500 ms for 5 s; since both peers do this toward each other from their shared socket, NAT mappings open on both
   sides (simultaneous open).
3. **Relay fallback**: if no direct connection within 5 s (or `force_relay`), establish the *same* end-to-end QUIC
   connection over a virtual `net.PacketConn` whose packets are wrapped in relay `DATA` frames. The relay sees only
   QUIC ciphertext.
4. While relayed, retry direct every 30 s; on success migrate new streams to the direct connection and close the relayed
   one after it drains. Report `PathKind` changes via `WatchEvents` and `ListPeers`.

RTT: `ControlStream` ping/pong every 5 s, EWMA; exported in `ListPeers` and Prometheus (`/metrics` on an optional
local-only debug port).

## Relay

`p2pgames-relay --listen :3478 --id eu-1 --control-plane-key <b64|url>`. Stateless apart from registrations.
* `REGISTER` verifies the CP-signed token (signature, not expired, `relay_id` matches) and the node signature over
  `p2pgames-relay-register|<relay_id>|<node_id>|<ts>` (|ts − now| ≤ 60 s) against the node public key carried in the
  token payload (`pk`), so the relay needs no database. Replies `REGISTERED{observed_addr}` (doubles as reflector).
  Registration expires after 60 s; nodes re-register every 25 s (also keeps NAT mappings warm).
* `DATA` is forwarded only to a registered node in the same `group_id`, rewriting the header to carry the source id.
* Per-group byte counters and token-bucket rate limit (`--group-rate-mbps`); Prometheus metrics on `--metrics :9090`.
* Multiple relays: the agent passes all relays; the mesh registers with each and prefers the one with lowest RTT that
  the peer also lists.

## Service addresses (no TUN)

Each service gets a stable loopback IP from `127.77.0.0/16`, allocated by the CP when the server is created:
`offset = uint16(fnv32a(service_id))`, mapped into `127.77.1.1 – 127.77.254.254` (skip `.0`/`.255` octets), linear
probing until unused within the group. Stored in `services.loopback_ip`; never changes for the server's lifetime (I7).
Works on Linux and Windows without configuration (the whole 127/8 is loopback on both). Ports are the game's own ports
(declared by the driver), so `127.77.12.34:25565` is what players type.

### Client side (`SetRoutes`)

For each route the mesh binds TCP and UDP listeners on `loopback_ip:port` on **every** node in the group, including the
host itself, and keeps them bound while the server is stopped (connections are refused / datagrams dropped) so the
address never moves.
* **TCP**: accept → open stream to `host_node_id` with `StreamOpen{service{service_id, epoch, port, TCP}}` → on accept,
  splice bytes both ways.
* **UDP**: each distinct client source address is a *flow*. First datagram ⇒ open a stream with
  `StreamOpen{udp_flow{…, flow_id}}`; payloads go as QUIC datagrams `[uvarint flow_id][payload]` in both directions.
  Idle flows close after 60 s. Datagrams larger than the QUIC max datagram size are dropped and counted.
* If the host is the local node, forward directly to `127.0.0.1:target_port` without QUIC.
* On route change (new host/epoch), existing streams are closed; new ones go to the new host.

### Host side (`SetHostedServices`)

The mesh accepts `service`/`udp_flow` streams only for `(service_id, epoch)` currently hosted; otherwise it replies
`StreamAccept{ok:false, reason:STALE_EPOCH|UNKNOWN_SERVICE}` and emits `RouteRejected` (stale routes rejected, M4).
Accepted traffic is forwarded to `127.0.0.1:target_port`.

### Internal services

`agent.chunks` (see `storage.md`) is exposed with `SetInternalServices`; any authenticated group peer may open
`InternalStream{name}` to it. `BindInternalForward` gives the local agent a `127.0.0.1:<port>` that tunnels to a peer's
internal service.
